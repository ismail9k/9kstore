# Owner Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner logs in at `/admin` on a laptop and manages products (bilingual text, price, code, sizes, colors with swatches, color × size stock, visibility, order) and store settings, all stored in Cloudflare D1 and read at request time.

**Architecture:** A server-only data layer (`src/lib/catalog`) wraps D1 with zod-validated `Product`/`Settings` objects whose nested parts (sizes, colors, photos, sold-out pairs) are JSON columns. A password login sets an HMAC-signed cookie checked optimistically in `src/proxy.ts` and again by `requireOwner()` in every admin page and server action. Admin pages under `src/app/admin` are server components wrapping small client components (shadcn/ui, dnd-kit) that call server actions with one validated object.

**Tech Stack:** Next.js 16.4 App Router on Cloudflare Workers via `@opennextjs/cloudflare` 1.20; Cloudflare D1 (Wrangler migrations, no ORM); zod 4; shadcn/ui (Radix base) + Tailwind 4; `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities`; WebCrypto for session signing; Vitest.

**Spec:** `docs/superpowers/specs/2026-10-19-owner-admin-design.md`

Intent-Issue: #2 — https://github.com/ismail9k/9kstore/issues/2

## Global Constraints

- Read `AGENTS.md` and the Next.js 16 docs under `node_modules/next/dist/docs/01-app/` before writing code: middleware is `proxy.ts`; `cookies()` is async; `cacheComponents` stays **off**.
- Every new binding goes in three places in `wrangler.jsonc` (top level, `env.staging`, `env.staging.previews`), then `pnpm cf-typegen`.
- `noUncheckedIndexedAccess` is on; indexed reads are `T | undefined`.
- Import from `src` with `@/`. Tests sit next to code as `*.test.ts(x)`, Vitest, logic only — no component or snapshot tests.
- Brand: off-white `#F1EDE7` page, near-black `#0A0A0A` text, green `#1F4F34` only for primary buttons, selected states and focus rings; shadcn tokens exactly as in `docs/brand/guidelines.md` "shadcn/ui theme tokens"; **no dark mode**; buttons are pills; font IBM Plex Sans Arabic is **not** this issue's job (customer pages, #4) — the admin keeps `system-ui`.
- dnd-kit is imported only from files under `src/app/admin/`.
- Owner-facing text never says slug, key, JSON, payload, D1, R2, migration. The slug field is labeled "Link name".
- Data is never cached: no `unstable_cache`, no `revalidate`, no `fetch` caching in the data layer.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never run `pnpm deploy` or `pnpm upload`.

## Review Focus

1. An Arabic-only English name (or one of only punctuation) must still save: `slugify` returns `""` and the server uses `"product"`; pinned in Task 2.
2. Removing a size or a color that has sold-out marks must silently drop those marks, not fail validation or leave orphans: pinned in Task 2 (schema) and Task 7 (reducer).
3. Sizes typed with stray spaces (`" M "`) are trimmed, and `"m"` vs `"M"` are distinct sizes; duplicates after trimming are rejected: pinned in Task 2.
4. A WhatsApp number pasted as `+20 10 1234 5678` or `010-1234-5678` must normalize to digits only, and letters must be rejected: pinned in Task 2.
5. A tampered, expired or foreign-secret cookie must fail verification and redirect rather than throw, and a Worker with no secrets must render the "not set up" page: pinned in Task 4.

**Interfaces:**
- Produces (password.ts): `timingSafeEqual(a: string, b: string): boolean` (compares UTF-8 bytes; different lengths → false after a full-length loop).

- Produces (secrets.ts, `server-only`): `getSecrets(): Promise<{ adminPassword: string; sessionSecret: string } | null>` — reads `ADMIN_PASSWORD` and `SESSION_SECRET` from `(await getCloudflareContext({ async: true })).env`, falling back to `process.env`; `null` when either is missing or `SESSION_SECRET` is shorter than 32 characters.
- Produces (session.ts, `server-only`): `COOKIE_NAME = "9k_admin"`, `SESSION_DAYS = 30`; `createSession(): Promise<void>` (sets cookie: `httpOnly`, `sameSite: "lax"`, `path: "/admin"`, `secure: process.env.NODE_ENV === "production"`, `maxAge` 30 days); `destroySession(): Promise<void>`; `getSession(): Promise<boolean>`; `requireOwner(): Promise<void>` — `redirect("/admin/login")` when not logged in or secrets missing.
- Produces (proxy.ts): `export async function proxy(request: NextRequest)` with `config.matcher = ["/admin/:path*"]`, behaving as the spec's "The owner login" bullet describes, plus header `X-Robots-Tag: noindex, nofollow`. It reads the secret via `getSecrets()`; when that returns `null` it treats every request as logged out (so `/admin/login` renders the not-set-up page from Task 5).
